Welcome to Cedar — User Guide & Documentation

Cedar is a local-first, zero-dependency static blog studio and publishing engine. Every article, page, photo, and theme setting you create belongs 100% to you as clean, portable files on your own hard drive—never locked inside a proprietary cloud database or subscription service.

1. Link Your Folder
Choose a folder on your computer (or restore a .ZIP backup) so Cedar auto-saves your work directly to disk.
2. Write & Design
Compose posts in the distraction-free block editor, organize pages & categories, and customize your theme in Design.
3. Publish 1:1 to Web
Push directly to GitHub Pages / Cloudflare Pages or export a standalone Web Site .ZIP that matches your preview 1:1.

Local Storage, Backups & File Structure

How Local Folder Sync Works

When you create or import a blog during setup (or in Publish → Storage & Backups), Cedar links directly to a folder on your computer. Every time you type, upload an image, or change a setting, Cedar writes the updated files to your local folder automatically.

  • Local Blog Folder vs. Web Export: Your local blog folder (and Export Local Backup .ZIP) stores everything—including unpublished drafts, hidden posts, and your studio configuration (editor/drafts.json and config.json).
  • Public Web Output: When you click Publish (GitHub) or Export Web Package (.ZIP), Cedar strips out all private drafts, hidden items, and studio files, compiling only your published site.
  • Why Browsers Block Selecting Desktop or Documents Directly: Chromium browsers (Chrome, Edge, Brave, Vivaldi) prevent websites from selecting top-level system folders like Desktop, Documents, or Downloads directly (showing a "contains system files" alert). Simply click New Folder inside the folder picker dialog (e.g., inside Documents), name a folder (such as Blogs or your blog name), and select that subfolder!
Your Local Blog Folder Layout
My Blog - a Cedar blog/
├── config.json                  # Site title, domain, theme, authors & categories
├── editor/
│   └── drafts.json              # Full workspace snapshot for instant studio reload
├── blog/
│   ├── drafts/<slug>/           # Unpublished drafts (index.md + draft.json + images)
│   ├── published/<slug>/        # Published articles (index.md + index.html + images)
│   └── hidden/<slug>/           # Hidden/archived articles (never exported to web)
├── pages/
│   └── published/<slug>/        # Standalone pages (About, Links, custom pages)
└── media/
    ├── branding/                # Site logo & favicon (logo.png, icon.png)
    └── authors/                 # Author profile avatar images

Writing Studio & Block Editor

Creating & Managing Posts

Click + New Post in the top bar (or inside the Home / Posts tabs) to open the focused Writing Studio.

  • Drafts, Scheduled & Published: Use the status control in the editor header to keep a post as a Draft, set a future date/time to Schedule it (automatically published based on the timezone configured in Site Info), or Publish immediately.
  • Post Settings Drawer: Click the settings icon in the editor topbar to customize the URL slug, category tag, publication date, custom read-time override, SEO meta description, or cover image.
  • Rich Content Blocks: Use the editor toolbar to insert headings, blockquotes, code blocks, dividers, callout alerts, YouTube video embeds, rich Link Bookmark cards, multi-image galleries, Share Article buttons, RSS Subscribe buttons, and dynamic Recent Posts or Individual Post embeds.
  • Visual Canvas vs. Markdown / Code Mode: Toggle between the visual WYSIWYG canvas and raw Markdown/HTML source inside the Post Settings sidebar whenever you want direct code control.

Pages, Categories & Links Studio

The Pages tab unifies your standalone static pages, category archives, and built-in utility pages in one place:

  • My Pages: Create custom standalone pages (such as /about/, /projects/, or /uses/). Published pages automatically appear in your site's top navigation bar unless hidden.
  • Categories: Add or rename categories right from the Pages tab. Every published post belongs to a category (defaulting to uncategorized) and generates a clean permalink at /<category>/<post-slug>/ plus a dedicated category archive page at /<category>/.
  • Links Studio (/links/): Click the built-in Links page to open Cedar's dedicated Linktree-style editor. Add social and project links, upload custom icons, and style the page with custom colors, gradients, or background patterns.
  • RSS Feed (/rss/ & /feed.xml): Unhide the built-in RSS page to enable automatic RSS 2.0 XML feed generation and display an RSS subscription page in your site navigation.

Media Library, Galleries & Privacy Sanitization

  • Automatic EXIF Metadata Stripping & WebP Compression: Whenever you drop or upload an image into an article, Cedar processes it client-side—stripping GPS coordinates, camera serial numbers, and EXIF metadata while converting to high-efficiency WebP.
  • Responsive Multi-Image Galleries: Dropping or selecting multiple images creates a responsive gallery grid (supporting 1, 2, 3, 4, or 5+ image bento layouts with a built-in fullscreen lightbox viewer).
  • Central Media Library: Visit the Media tab to browse every image across your posts, pages, and branding assets, inspect dimensions, copy paths, or clean up unused media.

Visual Design Studio & Themes

Open the Design tab to customize your blog's appearance with a real-time interactive preview:

  • Dark & Light Theme Palettes: Choose from curated dark and light editorial color schemes or define up to 3 custom 60/30/10 color palettes. Your chosen theme styles both your public blog and the Cedar studio interface.
  • Header & Masthead Controls: Adjust header alignment (Left, Center, or Split), toggle sticky header behavior, scale your brand logo and site title, and fine-tune navigation link spacing.
  • Homepage Layout & Typography: Configure the Hero Spotlight card, Recent Posts grid (1–3 columns, vertical cards vs. horizontal list), container width, and heading/body font pairings.
  • Save Design Changes: Click Save Design in the Design sidebar to commit your layout changes to your workspace and live preview.

Publishing to the Web (1:1 Export & GitHub Sync)

Cedar's compiler guarantees 1:1 visual and functional parity between what you see in the Preview tab and what visitors see on your live domain—with zero preview.html or localhost prefixes.

Option A: One-Click GitHub & Cloudflare Pipeline (Recommended)
  1. Create a GitHub Repository (Private Recommended): Create a new repository on GitHub and check "Add a README file" so the main branch is initialized immediately. (If you forget to add a README, Cedar will also bootstrap the initial commit for you automatically on your first publish.) Keeping your repository Private is recommended—Cloudflare can still deploy from a private repo while your source stays private.
  2. Generate a GitHub Personal Access Token (PAT): Go to GitHub Settings → Developer settings → Personal access tokens:
    • Fine-Grained Token (Scoped to 1 Repo): Under Repository access, select Only select repositories and pick your blog repo. Important GitHub UI Quirk: Before clicking Save/Generate, you must also scroll down to Permissions → Repository permissions → Contents and change it from No access to Read and write in the same step—otherwise GitHub silently discards your repo selection and resets the token back to Public Repositories (read-only)!
    • Classic Token (Account-Wide): Choose Tokens (classic) and check the top repo checkbox (Full control of private repositories). Note that Classic tokens apply to all repos on your GitHub account rather than a single repo.
  3. Save Credentials First, Then Test & Publish: In Cedar, open Publish → Publish to Web, click Add Repository, paste your repository URL (e.g., https://github.com/username/my-blog) and token, and click Save Credentials first. Once saved, you can click Test Connection to verify read/write access, then click the big Publish button to push your site to GitHub.
  4. Connect to Cloudflare Workers & Pages: Once you have published to GitHub at least once (so index.html and wrangler.jsonc exist in your repo), go to your Cloudflare Dashboard → Compute (Workers) → Workers & Pages → Create application → Import a repository, select your GitHub repo, leave all build settings at their defaults, and click Deploy.
  5. Connect Your Custom Domain in Cloudflare:
    • Add Domain & Update Nameservers: In Cloudflare's left sidebar, click Websites → Add a domain, enter your domain name, choose the Free plan, and copy the two Cloudflare nameservers (e.g., *.ns.cloudflare.com) into your domain registrar's Custom DNS / Nameservers setting.
    • Delete Default Registrar Parking Records (Prevents Error 522): Inside Cloudflare under Websites → [Your Domain] → DNS → Records, check if Cloudflare auto-imported a default A record (for your root domain) or CNAME record (for www pointing to a registrar parking page). Delete those default web parking records (leave any MX/TXT email rows intact).
    • Attach Domain to Your Worker: Go to Compute (Workers) → Workers & Pages → click your blog application → Settings → Domains & Routes → + Add → Custom domain, and add both your root domain (e.g., yourdomain.com) and www.yourdomain.com. Cloudflare automatically wires the Worker DNS route and SSL certificate in seconds.
Cloudflare & GitHub Troubleshooting Tips
  • Re-linking GitHub to Cloudflare (If Uninstalled): If you ever uninstall the Cloudflare app from GitHub, Cloudflare's dashboard can get stuck on the old connection and refuse to pop up the install prompt. Open github.com/apps/cloudflare-workers-and-pages directly while signed into GitHub, click Install, and select your repo to immediately restore the pipeline.
  • Cloudflare Worker Name Matching (wrangler.jsonc): Cloudflare's default npx wrangler deploy requires the "name" field inside wrangler.jsonc to match your Cloudflare Worker application name (which defaults to your GitHub repo name in lowercase). Cedar automatically sets "name" in wrangler.jsonc to your linked GitHub repository name so they match out of the box.
  • Site Times Out with Cloudflare Error 522: This means your domain's DNS table still has an old registrar parking A record pointing to a dead IP instead of your Worker. Delete the old A and www CNAME records in DNS → Records, then attach your domain under Workers & Pages → Settings → Domains & Routes → Custom domain.
Option B: Manual Web Export (.ZIP)

In Publish → Manual Web Export, click Export Web Site (.ZIP). Unzip and upload the folder to any static web host (Cloudflare Pages, Netlify Drop, Neocities, S3, Nginx, or Apache). Every post, page, and category includes its own pre-rendered index.html for instant loading and SEO.

Platform Compatibility (Windows, macOS, Linux & Chromebook)
  • Web Version (Hosted): Works out-of-the-box with direct local folder linking on all Chromium-based browsers (Chrome, Edge, Brave, Arc, Vivaldi, Opera) across Windows, macOS, Linux, and Chromebook.
  • Local Launcher (Offline Studio): Double-click cedar.bat on Windows or run ./cedar.sh on macOS and Linux to launch the local Python server on http://localhost:8080 (compatible with all browsers, including Safari and Firefox).
